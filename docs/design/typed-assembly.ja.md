# 型付き機械命令と生成位置の契約

[English](typed-assembly.en.md)

段階1の[単一命令API](typed-instructions.ja.md)と段階2の[Program・Object・出自対応](typed-program.ja.md)は実装済みです。Cerune側の型付き構築への移行は後続です。対象は現行x86-64の命令範囲とELF64/COFFです。Cerune言語への移植は[Sashimi #2](https://github.com/Cerune-Lang/Sashimi/issues/2)の別段階です。

## 目的と責務

確定済みの機械命令を値として受け取り、同じ入力からASM・Object・出自対応表を生成します。Ceruneの高水準IRを受け取ったり、ソースの意味をもう一度解釈したりしません。

| 担当 | 保持する処理・情報 |
| --- | --- |
| Ceruneなどの呼出し元 | 言語意味論、MIR/LIR、命令選択、ABI、runtime、ソース位置とOriginIdの対応 |
| Sashimi | 命令とオペランドの検証、符号化、配置、ラベル解決、再配置、ASM/ELF/COFF出力、生成位置 |
| リンカ・実行器 | 最終アドレス、外部シンボル解決、実行。Sashimiは暗黙に呼び出さない |

```text
呼出し元の命令選択 → 型付きProgram + 出自ID
                       ├→ ASM表示
                       └→ 検証・符号化・配置 → Object + 出自対応表
```

ASMとObjectが共有するのは確定済み命令です。出自観測のために命令・評価順・失敗条件を変更しません。

## 現行コードから移す情報

| 現行箇所 | 現在の処理 | 移行先 |
| --- | --- | --- |
| encode.rsのregister / operand | 文字列からレジスタ幅・種別、即値、アドレス、ラベル参照を読む | テキスト入力側。型付き入力は検証済みの値を渡す |
| encode.rsのvalidate / encode | 命令形式・幅・範囲の検査と符号化 | 両入力が共有するコア |
| parse.rs | セクション選択、データ、alignment、ラベル、公開属性、fixup解決 | 型付き項目の検証・配置 |
| format.rs | セクション・シンボル・再配置をELF/COFFに書く | 共通のObject出力 |
| Cerune emit.rsとruntime補助群 | ABI・命令選択・文字列化・出自ラベル生成 | 命令選択はCeruneに残し、文字列出力を型付き構築へ段階移行 |

parse.rsは未解決の `.L` / `cerune_` 名を拒否し、その他の未解決参照を外部シンボルにしています。これは現行テキスト入力の互換規則です。新コアへ名前の接頭辞による意味判定を持ち込みません。

## 型付き入力

`Program`は明示的なTarget、シンボル表、順序付きの項目列を持ちます。最初から任意ISA・任意セクションを一般化せず、Text・ReadOnlyData・Dataを対象にします。

| 要素 | 表す内容 |
| --- | --- |
| Instruction | 閉じたOpcode列挙と型付きOperand。未知の命令文字列を通す入口は設けない |
| Register / Operand | 汎用8/32/64bit・XMMレジスタ、即値、base/index/scale/disp、RIP相対・分岐参照。幅、番号、倍率を検査 |
| SymbolId / Symbol | Program内のID、名前、内部定義／外部宣言、ローカル／公開。内部定義は一度だけ必須 |
| Section / Label / Data / Align | 明示セクション、シンボル定義、バイト列、2の冪の整列。データにNULを暗黙追加しない |
| EntryId | 入力項目を特定する番号。診断と生成位置の対応に使う |
| OriginId / provenance | 呼出し元の不透明なu64 IDの集合、または明示的なSynthetic |
| Marker | バイトを生まない入力項目。ObserveOnly等の位置を残す |

即値は広い整数で保持しても、符号化時に命令形式ごとの範囲を必ず検査します。レジスタやシンボルの不正値、重複定義、未定義の内部参照、範囲外変位は成功値に変換しません。シンボル名はASMへ安全に表示できる文法を定義し、改行・NUL・ディレクティブの注入を拒否します。

外部シンボルは明示宣言が必要です。参照先を名前から推測しません。命令の参照からfixupを作り、配置後に解決または再配置へ変換します。初版は現行のtext内参照に限定し、任意データ内ポインタ・任意再配置の公開APIは後続です。

公開APIは次のとおりです。詳細な契約は[Program API](typed-program.ja.md)を参照してください。

- `render_asm(&Program)`：検証済みの命令・データをtargetに応じたASMへ表示する。
- `assemble_program(&Program)`：ASM文字列を経由せず、Objectと対応表を返す。
- `assemble(&str, Target)`：既存互換入口。段階的にProgramへ解析してコアを共有する。

型付き入力を一度文字列化して既存パーサーへ戻す実装を、移行完了とは扱いません。

## 出自対応表

位置はセクション内のバイトオフセットで、範囲は半開区間 `[start, end)` です。Objectファイル内オフセット、ASMの行番号、リンク後仮想アドレスとは別物です。

| ケース | 返す情報 |
| --- | --- |
| 1つのOriginから複数命令・非連続範囲 | 同じOriginIdに複数のEntryIdと範囲を保持。連続範囲へ勝手に統合しない |
| 複数のOriginが同じ命令へ対応 | 同じ範囲を複数IDから参照できる |
| Marker・長さ0のData・padding 0 | セクションと `start == end` の位置を保持。「記録なし」と区別 |
| prologue・runtime・alignment | Syntheticを明示。呼出し元が付けたIDがあればその関係も保持 |
| セクション切替・外部宣言 | セクション切替はEntryId、外部宣言はSymbolIdで記録し、架空のバイト範囲は作らない |
| 解決済み参照・未解決外部参照 | 参照元EntryId、シンボル、変位フィールド、解決／再配置の種別を保持 |

例として、Origin 7がtextの `[0, 3)` と `[8, 10)`、Origin 8のMarkerが `[10, 10)` に対応し、間の `[3, 8)` は合成paddingという結果を表せます。OriginIdはアセンブリ1回の入力内だけで解釈し、別Programとの同一性は保証しません。

同一の検証済み入力からObjectと対応表を一緒に生成します。観測だけを無効化した比較ではObject全体が一致することを要求します。既存の出自シンボルを追加する機能とは区別します。シンボル追加では表が変わるためObject全体の一致を要求せず、text/dataと再配置の意味を比較します。対応表は入力の変更や再符号化を行うAPIを持ちません。

Objectのヘッダ・シンボル表などを高水準ソースへ無理に帰属させません。初版で追跡する範囲は命令・データ・整列paddingと、それに結び付くシンボル・参照です。Object全バイトを網羅した証明は未対応です。

## 診断と互換性

型付き診断は操作段階、理由、EntryId、関連OriginId・SymbolIdを保持します。Ceruneは対応表からNodeId/SourceId/Spanへ戻します。Sashimiは架空のソース位置を作りません。既存 `Diagnostic.message` とASM行番号の診断は互換入口で維持します。

整列は現行のtext用0x90／data用0を明示的に維持し、短い分岐への最適化や命令再配置は導入しません。SymbolIdの内部番号がObjectのシンボル順を変えないよう、現行の決定的な順序も検査します。

## 実装順序と完了条件

| 段階 | 変更 | 検証 |
| --- | --- | --- |
| 1 | 型付き値・検証・直接符号化・ASM表示をSashimiに追加 | 既知の命令バイト、不正入力、型付き／テキスト入力の比較。最初は明示した有限ケースから増やす |
| 2 | シンボル・セクション・データ・再配置・出自対応を接続 | 両target、複数範囲・0バイト・Synthetic・宣言・padding・参照、観測有無の不変性 |
| 3 | Ceruneの命令選択とruntime補助を型付き構築へ移す | 135個の既存実行例、通常MIR/SSA、注釈有無、失敗診断・I/O順・外部ASM・リンク後実行 |
| 4 | 残ったASM再解析を除去し、移行用旧実装を退役 | 全ての通常生成経路が同じProgramからASM/Objectを出す。互換入口と独立テストを残す |

現行の全命令形式へ到達することが目標です。段階実装中の未対応機能は表で示し、Ceruneの本番接続を機能の少ない経路へ切り替えません。

切り出し時の `SOURCE_SNAPSHOT.json` は履歴として保持します。実装を変更する前に、初期4ファイルを固定fixtureへ保存して検証先を移し、現行ソースのハッシュを新しい値へ書き換えて「原本と一致」とすることは避けます。

## 現行の外部jmpとPIEリンク

Cerune PR #184の失敗注入用Objectで、外部mallocへのjmpがELFのPC32再配置になり、Linux CIのPIEリンクに拒否されました。固定版のcallはPLT32ですが、jmpは同じ扱いではありません。通常のCerune生成は外部関数にcallを使います。このテストもABIに従うcallへ修正し、PIEを無効化せず検証します。

型付きProgramは外部call・jmp・jccをPLT32にし、ASM表示でも@PLTを明示します。WindowsとLinux（PIE有効）でASM/Object双方のリンク・実行を検証しました。内部分岐・RIP相対データ参照も別に検証します。旧テキスト入口の外部jmpは互換性のためPC32のままです。

## 両リポジトリでの開発

SashimiのAPI変更とテストを独立PRにし、公開された完全なコミットIDをCeruneのCargo.tomlと両Cargo.lockへ反映します。Cerune側PRには対応するSashimi PRを記録します。未統合の依存がある間は、その状態を明記します。

隣接cloneのpath依存を共有設定へコミットしません。開発者はCeruneだけをcloneして依存を取得できます。ABI・出自契約の変更は日英で記録し、旧経路と差分検証してから接続を更新します。
